# Matchframe Esports 0.9.1-dev — development build

**Unsigned development build. Checked automatically on Linux and on a Windows CI runner, with kaiHUD 1.0.2 measured in Chromium. Not yet seen on your PC.**

**Coming from 0.9.0:** the program updates itself. Press **Restart now** in the status bar when the update has downloaded.

## kaiHUD moves smoothly

kaiHUD drew at 60 frames a second, but Matchframe gave it new game data only 10 times a second (since 0.6.0). kaiHUD's minimap slides each player's dot to its new spot over 0.1 s, speeding up and slowing down, so the dots surged and almost stopped ten times a second. That pulsing looks like a HUD running at 20 fps.

Now LHM HUDs get game data 20 times a second. Changes viewers must see at once still go straight away: the spectated player, round phase, bomb, deaths and score.

Measured with kaiHUD and a player running across the minimap:

| Updates a second | How evenly the dot moves (lower is smoother) | kaiHUD's page busy |
|---|---|---|
| 10 (before) | 0.70 | 16 % |
| **20 (now)** | **0.25** | **21 %** |
| 50 (every packet) | 0.32 | 34 % |

More than 20 is no smoother, and on a slower PC it makes the HUD drop frames.

## Drawing the HUD on the CPU

Not added. The HUD already draws at 60 fps, and the choppiness came from the update rate, not the graphics card. Drawing a 1920×1080 transparent HUD on the CPU every frame would be slower, and it would switch the whole program off the graphics card.

If CS2 leaves the graphics card no room (an uncapped frame rate), cap it in CS2's console, for example `fps_max 240`.

## The HUD Library says when a HUD draws too few frames

A HUD output that draws under 40 frames a second now turns amber, like one that pauses. Its **Outputs** tab says where and what helps:
- **OBS:** turn on browser source hardware acceleration, and set OBS to 60 fps.
- **Desktop HUD:** cap CS2's frame rate.

Hover **Desktop** or **OBS** on the HUD's card to see its frame rate. The support file now includes each running HUD's frame rate too.
