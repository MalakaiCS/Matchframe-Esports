# Matchframe Esports 0.4.0-dev — development build

**Unsigned development build. Installed and checked on a Windows CI runner and against a stand-in CS2 (a test console and test game data). Not yet used against a real CS2 client.**

**Coming from 0.3.0:** the program updates itself. Press **Restart now** in the status bar when the update has downloaded, or quit and open it again. Your HUDs, settings and sign-in are kept.

## What's new

### One-button Auto Director

**Start Auto Director** is at the top of the HUD Library and in Live Control. Press it while CS2 is spectating a match or playing a demo. It checks everything in order, fixes what it can, and then moves the camera for you. You don't need to type console commands or run setup tests.

| Check | What it does |
|---|---|
| CS2 console | Uses the console of the CS2 that **Start CS2** started, and sets up the camera control. If CS2 was started in Standard mode, it switches **Start CS2** to Tools mode and asks you to restart CS2 with it. Tools mode needs the free **CS2 Workshop Tools**. It also turns off CS2's own auto director, which would fight Matchframe's cuts. |
| Game data | Waits for CS2's game data with a map loaded. |
| Account | Checks your sign-in and hours once, at Start. A match that is already running is never cut off. |
| Player switching | Switches CS2 to a player and waits until the game data shows that player. If CS2 isn't spectating yet, it tries again every 10 s. |
| Cinematic cameras | Shows one camera and asks CS2 where the camera is (`getpos`). If the answer doesn't match, it tries CS2's other camera-mode numbering, and then the demo fix `cl_demo_freecam 0`. If cameras still don't work, it follows players only and says why. |
| Auto Director | Starts directing: player POVs, plus cinematic cameras and nade cams if those are switched on and working. |

While it runs:

- **You can always take over:** pick a player in CS2 or in Live Control, and the Auto Director takes the camera back after 8 s. You can choose 5, 8, 15 or 30 s, or only when you press Start.
- **Take over** in the top bar keeps the camera yours until you press **Resume automation** or Start.
- **Stop** stops it, and so does the emergency stop or setting the Observer to Off.
- **Nade cams** need the top plan. Without it, the Auto Director films with cinematic cameras and POVs.

Each check is done once per CS2 build. After that, Start goes straight to directing.

### Cameras and camera paths on every active-duty map

- **Built-in cameras for all nine maps:** 92 cameras and 32 camera paths on Ancient, Anubis, Dust II, Inferno, Mirage, Nuke, Overpass, Train and Vertigo. They cover the bombsites, mid, spawns and the main routes.
- **In freeze time:** Observer & Cinematics flies one camera path per round, taking turns through the map's paths, when it fits in the time left. The bomb and big-fight cameras use the built-in cameras too.
- **How they were placed:** from the maps' navigation data, keeping only spots with a clear line of sight over the map and checked against CS2's radar and real CS2 match positions.
- **Not seen in game yet:** they haven't been checked by eye in CS2. A camera could clip a prop the navigation data doesn't describe. Switch them off in **Maps & Cameras → Built-in cameras**, or mark a single camera Invalidated, and it's never used again.
- **Known gaps:** Train has no CT spawn camera, Vertigo no T spawn camera, and Nuke and Overpass no mid camera.

### HUDs keep up with the game

Switching the spectated player used to show on the HUD a few hundred milliseconds late. Every step between CS2 and the HUD is now faster:

- **CS2 sends game data every 20 ms** instead of every 100 ms. The program updates its config file in the CS2 folder when it starts, and CS2 reads it when CS2 starts, so restart CS2 once after updating.
- **Matchframe HUDs** get a new spectated player, round phase, bomb state or death straight away. Before, there could be up to 100 ms of waiting.
- **LHM-format HUDs** (such as kaiHUD) get each packet before Matchframe does its own work.
- **Live Control** shows the new spectated player at once.

Measured on the test machine: a POV switch reaches the HUD in about 6 ms. From the game data arriving to the new player card on screen in a browser takes about 15 ms.

### Camera control that confirms itself

- **No more "Unverified" by hand:** player switching, static cameras, camera readback, observer modes and camera paths are confirmed from CS2's own feedback the first time they're used, and remembered for that CS2 build.
  - Player switching: the game data shows the player you picked.
  - Cameras: `getpos` answers with the camera's position.
- **Player cards work straight away:** clicking a player card in Live Control works before player switching is confirmed, because the click is the check. This fixes "POV control unavailable — Player selection: unverified".
- **Camera paths** are flown over the console: `spec_goto` 60 times a second along the path.
- **Camera-mode numbering:** if CS2 numbers the free camera `spec_mode 4` instead of `6`, Matchframe notices from `getpos` and keeps the numbering that works. The same goes for the player view: if going back to a player leaves the camera free, Matchframe tries the other number and keeps it.
- **Players by name:** players are selected with `spec_player "<name>"`. Names with quotes, semicolons or backslashes, and names two players share, can't be selected by name.

## How to test

1. Update to 0.4.0 (**Restart now** in the status bar), then restart CS2 so it picks up the faster game-data settings.
2. Install the free **CS2 Workshop Tools** in Steam (Library → Tools → Counter-Strike 2 Workshop Tools) if you haven't.
3. In the HUD Library, press **Start CS2**. If CS2 is already running in Standard mode, close it first.
4. Spectate a match (GOTV, a spectator slot) or play a demo.
5. Press **Start Auto Director** and watch the checks. Each line says what it's doing or what it needs.

If a check stays on a message, the message says what to do. The full log is in Settings → General → Open data folder → `logs`.

## Checked automatically

This release is published only after these pass:

- **Stand-in CS2:** a test console that answers `getpos`, with game data that follows `spec_player`. The Auto Director goes from Start to directing. It waits for the console and switches to Tools mode, confirms player switching and the camera, learns the other camera-mode numbering, flies a camera path in freeze time, gives the camera back after a manual pick, and stops.
- **HUD speed:** a POV switch must reach a Matchframe HUD and an LHM-format HUD within 50 ms while CS2 sends 20 updates a second. The 0.3.0 code fails this check.
- **Built-in cameras:** placed on CS2's radar for every map. Their sight lines were checked against the navigation data, and the map packs validate against the map-pack schema.
- **The installed program on a Windows runner:** the same checks as 0.3.0, including the transparent desktop HUD and the update files.
