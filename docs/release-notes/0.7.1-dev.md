# Matchframe Esports 0.7.1-dev — development build

**Unsigned development build. Checked automatically on Linux and on a Windows CI runner. The HLAE script was tested against a stand-in for HLAE, not yet inside a real CS2.**

**Coming from 0.7.0:** the program updates itself. Press **Restart now** in the status bar when the update has downloaded. To use the HLAE camera, start CS2 with **Observer tools + HLAE** (Start CS2).

## Every camera shot through HLAE

As you asked, and as Lexogrine HUD Manager does: with CS2 started in the **Observer tools + HLAE** mode, HLAE now plays every free-camera and moving shot. That covers:
- the map's cameras and their slow turns;
- the team shots gliding round the players;
- the winners after the round, half time and map end;
- camera paths and moving shots.

- **How it works:** Matchframe loads a small script into HLAE when the console connects, and the script connects back to the program. Each shot goes to HLAE as a timed set of camera poses, and HLAE sets the view on every frame. Moves are as smooth as your frame rate and no longer depend on console timing, resends or `getpos` checks.
- **Confirmed by HLAE:** a shot counts as on screen when HLAE has drawn it.
- **Back to the player** as soon as the director picks one. If the program closes or loses the connection, HLAE stops drawing straight away and CS2's own view comes back.
- **Without HLAE** (Observer tools mode, or HLAE not connected yet), shots go over the console as in 0.7.0.
- **On the Auto Director card:** whether the HLAE camera is connected and how many shots it has played. **Camera shots through HLAE** (on) can switch it off. The support file includes it too.
- This replaces 0.7.0's experimental "camera paths through HLAE" option.
