# Multi-PC setup

Typical split: **Observer PC** (CS2 observer client), **Production PC** (OBS + Matchframe), optional **Replay PC**.

- **Replay PC:** a second computer with its own CS2, OBS and Matchframe that films the kills the main camera misses and sends the clips to the main PC, which replays them between rounds. It works best a few seconds behind the main PC (a CSTV with more delay, or a second CSTV on the server): then it knows each missed kill before it plays there and gets the camera on the killer first. Setup is in [Replay PC and automatic replays](replay-pc.md). On the main PC, **Replays & Production → Replay PC → Let other computers on the network connect** restarts the engine listening on the network (the same as `MATCHFRAME_HOST=0.0.0.0`); access still needs a token or code.

- The Matchframe program runs the engine on the production PC. Set `MATCHFRAME_HOST` to the production PC's LAN address only if other machines must reach it, firewall ports 37210–37212 to the production subnet, and give each remote position its own role-scoped token (**Devices & Integrations → Tokens**, e.g. role *observer* or *producer*; never the owner token).
- **Extra operator positions** (graphics, replay, a second observer desk): install the same program and choose **File → Connection settings → Connect to the production computer** with the production PC's address (e.g. `192.168.1.20`, port 37211 by default) and that position's token. The program then runs no engine of its own and shows the production computer's console with the token's permissions; the window title shows the connection. The token is stored encrypted with the Windows credential store. **Connection settings → This computer runs the production** switches back. The console is never served to browsers.
- GSI: on the observer PC, write the GSI config with the receiver URI pointing at the production PC (`POST /api/v1/setup/write-gsi-config` with `host` set to the production PC's LAN IP, then copy the file to the observer PC's `game/csgo/cfg` if Matchframe cannot reach that disk).
- Observer control across machines: the console channel is loopback-only by design and keyboard input must happen on the observer PC itself. Run a second Matchframe engine on the observer PC as the control agent, or operate POVs manually on that machine. A dedicated remote observer agent with authenticated transport is planned (FEATURE_COVERAGE F02/F12).
- Video: capture the observer PC through a capture card or another tested transport. NDI is optional and not required for local Game Capture; untested transports are labelled as such.
- Clock sync between PCs helps but does not prove that two clients show the same game instant; delayed outputs must be aligned by measurement.
