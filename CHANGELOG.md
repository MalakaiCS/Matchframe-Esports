# Changelog

All notable changes to Matchframe Esports. Versions follow semantic versioning once releases start; this is the pre-release development line.

## [0.1.0-dev] — unreleased

### Added
- Shared zod contracts with JSON Schema and OpenAPI generation.
- CS2 GSI ingest with token authentication, absent/empty/null distinction, epochs and round attempts, duplicate and out-of-order rejection, pause-aware match clock, derived events with explicit evidence levels, capability sampling.
- Universal utility tracker for HE, flashbang, smoke, Molotov, incendiary and decoy from both teams anywhere on the map, with per-type profiles, prediction kept separate from confirmation, fire-area linking, inventory-based Molotov/incendiary resolution, entity-ID reuse handling.
- Map runtime: data-derived regions and floor grids, level separation, calibrated-only radar, schematic radar transform, camera coverage and authoring from `getpos`, revision invalidation.
- Director baseline-1: anticipation/readiness/information features, interaction clusters, crossfires, isolated aggressors, utility opportunities with the Inferno Bottom Banana rule as configuration, explainable weighted candidates, hysteresis planner, cinematic budget and interruption.
- Control arbiter: single writer, ownership generations, sticky manual takeover, emergency stop, confirmation from observed feedback, bounded retry, leases.
- Observer adapters (none, simulation, direct console — unverified, keyboard — unverified).
- Local engine: SQLite persistence with migrations/backups, REST + WebSocket APIs with roles and audit, read-only overlay server, HUD packages and outputs with draft/publish/rollback, veto with captain links, series rules, sponsors with delivery acknowledgements, automation rules, program state machine, replay queue (OBS replay buffer provider; bridge contract), demo library with safe retention, setup tests, statistics, broadcast report, player-camera routing, MatchFrame bridge client, event package export/import, labelled simulation.
- Broadcast HUD renderer with Classic, Minimal and Arena presets and nine variants.
- Electron desktop shell with engine supervision, hardened renderer, safeStorage-protected credentials and global emergency stop; `pnpm smoke:desktop`.
- Operator console (16 screens + captain page) with live control, setup checklist, production, demo and training screens.
- Python demo pipeline (extract/validate/verify, map packs, measured utility profiles, causal features and labels, leakage checks, match-level splits, LightGBM training, evaluation, export, registry) and its engine integration (Demo Library, Training Service).
- Live contact-model runtime in shadow with rejection of live-incompatible or corrupt models; TypeScript/LightGBM parity test.
- Measured utility profiles in the live tracker with uncertainty floors.
- Device control-surface API and tally; event stages with standings and single-elimination brackets on studio HUD panels; HUD Composer offsets applied on air.
- Replay playout confirmed from OBS media status (falls back to LIVE when OBS does not report playback).
- Extension guide and example HUD package; map coverage generator; simulated soak script; Windows NSIS installer and portable zip build.

Access is protected by a per-HUD cookie. Google Fonts are allowed for these HUDs, and a TEST DATA label shows over them during test data. Image inputs, keybinds and player cameras are not supported.

Console status on the Counter-Strike 2 card; launch mode, console port, extra launch options and HLAE.exe in Settings → Setup → Start CS2. Updates download in the background and install on quit, or straight away with **Restart now** in the status bar; the program never restarts on its own. **Settings → General → Program** has the version, Check for updates, What's new, Download updates automatically, Connection settings and Open data folder. 0.2.0 has no updater, so the next version is installed once by hand.
- **Built-in cameras checked against CS2's own geometry** (version 0.4.2, ADR-025): the built-in cameras and paths are rebuilt from CS2's navigation meshes and collision meshes for the current build (1.41.9.2, build 26144732, from awpy-data, read with awpy 3.1.1).
  - **Checks:** every camera has clear space around it, sees its area's centre and at least half the area (median 86 %), and has an open view. Every path's real flight curve is clear of walls and keeps the area in view.
  - **Before:** in the 0.4.x cameras, 30 of 92 looked through a wall or sat inside geometry.
  - **Now:** 104 cameras and 81 paths (orbits of at most 10 s, push-ins, and sideways drifts where there is no orbit).
  - **Gaps filled:** Train CT spawn, Vertigo T spawn, and a mid stand-in on Nuke (Outside), Train and Overpass (Connector).
  - **Generator:** `scripts/generate-map-cameras.py`; the old CS:GO-nav generator is now `scripts/generate-map-regions-csgo-nav.py`.
- **Freeze time all cinematic and smooth, pauses, HUD smoothness** (version 0.6.1, ADR-033):
  - **Director:** freeze-time spawn shots share the whole freeze time (4–12 s each, at most four, the last until live) and chain with no player view between (`chain` on candidates). Each turns in the game (`panDegPerSec`, ≤ 3°/s, ≤ 30°). No camera paths in freeze time unless `cinematic.freezeTimePaths`. In a tactical or technical pause: a still shot of the calling team's spawn until live (reason `PAUSE`).
  - **Console adapter:** pans with `cl_yawspeed` and `+left`/`+right`, centred on the camera's aim, released at the planned end or before the next command, checked once with `getpos`; streamed paths and follow cams at 128 poses a second, evenly paced.
  - **HUD outputs** report how smoothly they draw (frames a second, longest pause) every 5 s; the HUD Library shows a stuttering output in amber with what helps; pauses of 250 ms or more go to the director log.
- **Out of the freeze-time shot on time** (version 0.6.1, ADR-032):
  - **Fixed:** the camera staying on a freeze-time shot into the live round. Game data from just before a camera no longer clears the adapter's free-camera flag (1.5 s), and the in-eye numbering is switched only after 2 s of game data still showing the free camera across the director's retries; the numbering the game data confirms is kept, repairing a wrong one saved by 0.6.0.
  - **Run behind other windows** game option (default on): `engine_no_focus_sleep 0`, `snd_mute_losefocus 0`.
  - **Director log:** `logs/director.log` with console lines, arbiter events, decision changes and game data changes; its last 400 entries in the support file.
  - **Tests:** Dust2 freeze time to live against the real engine with game data 250 ms late (fails on 0.6.0 like the owner's recording); stand-in console tests for the in-eye numbering.
- **Team shots and no movement keys** (version 0.6.2, ADR-034):
  - **Fixed:** cinematics sliding into walls and floors ("in the ground" on Mirage). 0.6.1 turned freeze-time shots with `+left`/`+right`, which strafe the camera in CS2. Every moving shot is now sent as `spec_goto` poses by Matchframe (64 a second, no busy loop): `CameraMotion` with `pose(t)`, `panMotion`, `glideMotion`.
  - **Team shots in freeze time:** each team framed from where its players stand with the map's free-space grid (`frameTeam`): a little above head height, a few hundred units away, everyone in the picture and seen, from the side they face, nobody in the foreground, no wall in front of the lens; gliding about 10° round them. One team then the other, before the spawn cameras; the pause shot is the team's still shot.
  - **Built-in cameras:** the generator rejects a spot with a wall at the lens (more than a quarter of the 106° picture within 150 units): 12 dropped, 13 moved, 379 in all. Every camera checked for sitting inside geometry or under a floor: none.
  - **Tests:** framing on flat ground and CS2's grids for both spawns of all nine maps; director on Mirage's grid; a stand-in console where `+left`/`+right` strafe; Dust2, Mirage and Auto Director e2e.
- **Real spawns, Cache** (version 0.6.3, ADR-035):
  - **Spawn areas from pro demos** (`scripts/set-spawn-regions.py`): the seven pool maps' `t_spawn` / `ct_spawn` regions are where players stood at the end of freeze time (they were 100–500 units off; Ancient's and Anubis's CT spawns missed entirely). Spawn cameras and paths regenerated.
  - **Cache:** map pack from a pro demo's place names (46 areas), free-space grid and 87 cameras / 10 paths from CS2's meshes; in the default event pool with Ancient, Anubis, Dust II, Inferno, Mirage and Nuke.
  - **Team shots tuned on real positions:** finer spots (48 bearings, 6 distances, up to 300 units high), a size score, and a well-sized four over a distant five. Every round of the seven demos framed (272 shots).
- **Cinematics that hold, matches and match graphics** (version 0.6.0, ADR-031):
  - **Director:** a cinematic is noted before it is sent and never sent twice in a round (played or failed); repeated output carries no intent; game data that lags the console no longer ends a shot (600 ms settle) or looks like a manual takeover (any confirmation starts the arbiter's grace, catch-up is never an external change). Freeze time: up to two establishing shots of the spawns with players, each in full (≤ 7 s). First person for the first 10 s live. Follow cams at most once per map, streamed with a 1 ms timer and dead-reckoned positions. Nade cams on by default, threshold 0.28.
  - **LHM HUDs:** game data sent at most 10 times a second unless something on screen changes (kaiHUD baseboard 32 → 55 fps at a sixth of the CPU).
  - **Matches:** Create match always shown; new teams made in the form.
  - **Match graphics:** for every match, Highlights / Full replay / Live thumbnails, an Up next screen, and a stinger and replay stinger (QuickTime files of PNG frames with alpha, 60 fps), drawn in the program; engine storage and routes; **Put the stingers in OBS** sets the `Matchframe Stinger` and `Matchframe Replay Stinger` transitions (cut at 900 ms); activating a match switches them.
  - **OBS:** transition changes wait until OBS reports them (fixes replays cut with the previous transition).
- **Replay PC: the relative forms of `demo_gototick`** (version 0.5.3): going back is sent as `demo_gototick -N relative` and going forward to live as `demo_gototick N relative`, the forms the owner uses on live CSTV (0.5.2 sent the forward skip with `1`).
- **Replay PC on the same CSTV goes back 7 s and stays there** (version 0.5.2, ADR-030 update):
  - **Going back:** on a live CSTV connection CS2 can go back (`demo_gototick -448` is 7 s). When the replay PC is at the main PC's time, it goes back once to 7 s behind (5, 7 or 10 s) and keeps playing from there, so every missed kill is known before it plays there. It goes back again after a reconnect or map change.
  - **Settings:** `replayPc.sameCstv`: `stay_behind` (default), `each_kill` (0.5.1's rewind, migrated), `off`; `replayPc.behindMs`.
  - **The command:** going back is now sent as `demo_gototick -N`.
  - **Measuring:** the delay is carried across a jump in the replay PC's own round clock, so going back right after linking is seen at once.
  - **Corrected:** 0.5.1 said only CSTV+ streams could go back.
- **Replay PC behind the main PC, or rewinding** (version 0.5.1, ADR-030):
  - **Measuring:** the replay PC works out how far behind the main PC its game is, from the two round clocks and the kills both see. The main PC now reports its round clock and recent kills, each judged with its exact camera history.
  - **Behind (a CSTV a few seconds later):** every kill the main camera missed is known before it plays on the replay PC. Its director is pinned to the killer for the lead-up and the kill, then the clip is sent. Of two kills it can't both film it keeps the better one, and switches to a multi-kill.
  - **Rewinding (experimental, setting `replayPc.rewind`, off):** at the same time as the main PC, a missed kill the replay PC's camera didn't have makes CS2 go back (`demo_gototick`, CSTV+ streams only), the kill is filmed, and CS2 skips forward to live. A CSTV connection that can't go back is detected and reported.
  - **Live path:** the main PC's own verdict for a kill now decides whether the replay PC's clip is a missed kill, another angle, or not needed.
  - **Replay PC panel:** how far behind, what it is filming, kills it couldn't film with the reason, the rewind switch, and the server lines for a second CSTV.
- **Replay PC and automatic replays** (version 0.5.0, ADR-027):
  - **Replay PC:** a second computer with its own CS2, OBS and Matchframe, linked to the main PC by address and code. Its director avoids the main PC's player. It sends the kills the main camera missed (or showed only from the victim) as clips from its OBS replay buffer.
  - **Automatic replays:** the main PC plays them between rounds by itself, best first, never during a live round or over the operator's program choice. They come with slow motion, a replay transition and a one-click OBS replay scene.
  - **Big plays on the main PC:** it can replay 3K+ and won clutches its own camera showed.
  - **Network:** the program's switch lets other computers connect.
- **Clutch mode** (version 0.5.0, ADR-028): in a 1vX the director stays with the clutcher, with no cameras mid-clutch, the chase view while no opponent is near, a 1v3 banner and a replay of a won clutch. Setting `autoDirector.clutch`, on.
- **Sightlines and follow cams** (version 0.5.0, ADR-028):
  - **Grids:** free-space grids for the nine maps, from CS2's collision meshes (`scripts/generate-map-grids.py`, 12-unit cells, 1.5 MB).
  - **Cuts before the fight:** the director knows when opponents see each other now or in the next 1.6 s, and cuts before the shooting.
  - **Follow cams:** a free camera behind a running player in quiet moments, streamed over the console at 60 Hz and kept clear of walls with the grid. Setting `autoDirector.followCams`, on.
- **HUD graphics timed to the shots and OBS scene automation** (version 0.5.0, ADR-029):
  - **Graphics:** economy and round MVP in freeze time, player cards on long holds (player views only), the clutch banner, and LHM HUD pages (kaiHUD's Player Highlight and Match stats) through OBS sources.
  - **OBS:** timeouts and pauses to the break scene, map end to the studio scene, and a replay transition.
- **LHM HUD pages, logos and image inputs** (version 0.5.0):
  - an LHM HUD's own pages (hud.json variants) open with `?view=` and are listed with their OBS addresses;
  - team logos are sent as an address kaiHUD can use directly;
  - image inputs (kaiHUD's baseboard sponsors) are supported.
- **Cameras for every named area** (version 0.4.3, ADR-026): `scripts/generate-map-cameras.py` now also places cameras on every named area beyond the bombsites, mid and spawns, with the same CS2 collision checks (at least 45 % of the area in view, median 86 %). 391 cameras (287 new) cover 200 of the 227 named areas; 27 small or enclosed areas (tunnels, ladders, small rooms) have no spot that passes. They are tactical and utility cameras for the live round and round end, so big-fight overviews and nade cams work across the whole map; they have no paths.
- **Chase cam** (version 0.4.3, ADR-026): the Auto Director shows the spectated player in CS2's third-person chase view while they plant or defuse the bomb and when their team wins the round, then goes back to first person. It holds each view at least 1.5 s, never during a cinematic, and only while the director has the camera. Toggle **Chase cam** on the Auto Director card (`chase` in `PUT /api/v1/director/auto/settings`, default on). By hand: Shift-click a player card or Shift + number key in Live Control, or `view: "chase"` on `POST /api/v1/observer/commands`. The console adapter sends the chase command after `spec_player`, confirms it with `getpos` (the camera at least 40 units across from the player), tries the other `spec_mode` numbering once if not, and keeps whichever works.
- **Hide CS2 kill feed** (version 0.4.1, HLAE): a switch on the Counter-Strike 2 card that blocks CS2's own kill feed with `mirv_deathmsg filter add block=1`, so only the HUD's kill feed shows. With Hide game HUD on (`cl_draw_only_deathnotices 1`), the crosshair stays. Checked against HLAE's CS2 source: a filter rule with no player match applies to every kill notice.
- **One-button Auto Director** (version 0.4.0, ADR-024): **Start Auto Director** on the HUD Library and Live Control. It checks and fixes the CS2 console (switches the launch mode to Tools, selects the console camera adapter, turns off the game's own auto director), waits for game data, checks the account at Start (a running match is never cut off), proves player switching and the cameras on this CS2 build, then directs in the richest mode that works. Toggles for cinematic cameras and nade cams. It takes the camera back 8 s after you pick a shot yourself (5, 8, 15, 30 s or only on Start), and after data gaps; Take over holds until Resume automation or Start. Stop, the emergency stop, Off or the hours ending at a map change stop it. API: `GET /api/v1/director/auto`, `POST /api/v1/director/auto/start`, `POST /api/v1/director/auto/stop`, `PUT /api/v1/director/auto/settings`.
- **Built-in cameras and camera paths for every active-duty map** (version 0.4.0, ADR-024): 92 cameras and 32 freeze-time paths for Ancient, Anubis, Dust II, Inferno, Mirage, Nuke, Overpass, Train and Vertigo. They were placed by `scripts/generate-map-cameras.py` from the maps' navigation meshes (awpy 1.3.1, MIT) and checked against CS2 radar and demo data. New map packs for Dust II, Mirage, Nuke, Train and Vertigo. They are used without validation unless switched off in Maps & Cameras (**Built-in cameras**, `PUT /api/v1/cameras/built-in`). Observer & Cinematics flies one path per round in freeze time.
- **Console control that confirms itself** (version 0.4.0): player selection is confirmed when the game data shows the requested player; static cameras, readback and observer mode when `getpos` returns the camera's pose; camera paths (`spec_goto` streamed at 60 Hz) once the static camera is confirmed, and again at the end of the first path. If `spec_mode 6` doesn't move the camera, the adapter tries CS2's enum numbering (`spec_mode 4`) and keeps whichever works; the in-eye command is learned the same way from the game data. Player cards and camera requests work before confirmation, because each request is itself the check. The simulation flies camera paths.

### Changed
- **HUDs follow the game much faster** (version 0.4.0):
  - **CS2's sends:** the game-data config now lets CS2 send every 20 ms instead of 100 ms, with a 0.5 s timeout instead of 1.1 s. The program refreshes its existing config when it starts; CS2 picks it up when it starts.
  - **LHM-format HUDs:** they get each packet before Matchframe's own processing.
  - **Matchframe HUDs:** a new spectated player, round phase, bomb state or death is pushed straight away; other changes at most every 33 ms with a trailing push, instead of every 100 ms. The HUD state is built once per output.
  - **Live Control:** the console also updates at once when the spectated player changes.
  - **Measured:** a POV switch reached the HUD socket in about 6 ms (up to 100 ms before), and the painted HUD card in Chromium in 15 ms.
- **The program's own title bar and a HUD-manager layout** (version 0.3.0): no Windows title bar or menu bar; the console's header is the title bar (large page title, game, data state, Observer, Stop automation, account), with the window buttons drawn in the program's colours. Sidebar with the version, accent-filled active item and an edge tab to collapse it. The HUD Library has switches for Test data, Show HUD graphics and Utility on the radar, a Counter-Strike 2 card (status, `cl_draw_only_deathnotices 1` with Copy, Launch CS2, Setup), an **Add HUD** menu, HUDs grouped by category in folding groups, and list rows with Settings, Preview, Copy OBS Browser URL, more actions, a **Desktop** switch and an arrow that opens the details under the row. The layout follows common HUD-manager patterns; no code, artwork or wording from other HUD managers is used.
- **Signing in is optional** (version 0.2.0, ADR-021): the program opens without an account; sign in under Settings → Account to use the Auto Director on live matches.
- **A cleaner program** (version 0.1.3): sentence-case headings and labels, fewer boxes and badges, disabled-button reasons on hover, a compact top bar (connection, Observer, hours, OBS) and a grouped sidebar with short names. Every screen was tidied, with technical detail and rarely used options folded under disclosures (nothing removed). Live Control has one Camera and one Observer panel; its duplicate Stop automation button is gone (the top bar's stays).
- **The Matchframe Esports logo** (`assets/brand`): program top bar and sign-in screen, Windows program and installer icon (`apps/desktop/build/icon.ico`), website header, footer, favicons and social preview image (`og:image`, filled with `MF_CLOUD_PUBLIC_URL` when the website is served). Website colours retuned from violet to the logo's blues; website product screenshots retaken from the 0.1.3 program.

### Fixed
- **Game options no longer switch each other off** (version 0.4.1): turning on one switch on the Counter-Strike 2 card (for example Hide end-of-match screen, then Team colours in kill feed) reset the others to their defaults. Each switch now changes only its own option.
- Oversize uploads now get a 413 response instead of a connection reset; per-route upload limits.
- Replay queue state errors return 4xx; nested database transactions use savepoints.
- Match creation keeps the stage; the broadcast report's cut rate uses the correct window.
